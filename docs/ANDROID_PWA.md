# Kyalulu for Android — personal-server PWA

この文書は直接HTTPS接続の手順です。ポート開放なしの暗号化中継方式は [Kyalulu Remote](REMOTE.md) を参照してください。Remoteは現在、公開判定前の開発候補です。

Androidを優先した、ホーム画面に追加できるWebアプリです。既存のKyalulu Runtimeのキャラ・履歴・記憶を、同じサーバーに接続したPCとスマホで利用します。モデルの推論はPCまたはサーバーで実行します。

## 対象範囲

- トーク、キャラクター、つくる、設定の4つを中心にしたモバイル画面。
- 自分のPC／自分のクラウド上に置いたKyaluluを選んで開く接続先リスト。
- 短時間・1回限りの登録コード、端末別の認証Cookie、登録解除。
- 会話ごとの端末内下書き、生成IDによる送信結果の照合。切断だけを理由に自動再送しません。
- インストール案内、更新確認、明示的な更新、オフライン時の案内。
- キャラ作成、ファイル／テキストの取り込み、記憶の確認・訂正など、既存の会話機能。

**1台のRuntimeを1人で管理し、自分の複数端末から利用する構成です。** 登録された端末は同じ会話データを扱います。複数ユーザーの権限分離を備えた公開SaaSではありません。マネージドKyalulu Cloud、接続先をまたぐ自動同期、スマホ単体でのLLM実行、Google Play配布は対象外です。

## スマホで始める

1. PCで `pnpm --filter web build` を実行します。
2. [ホームサーバー起動手順](../scripts/HOME_SERVER.md)に沿って、Androidが信頼できる証明書を使ったHTTPSサーバーを起動します。既存データで続きを話す場合は、Desktopと同じデータ保存先を指定してください。別の保存先は別環境になります。
3. サーバー側で `scripts/home_server.py code` を使い、端末登録コードを発行します。
4. AndroidのChromeでサーバーのHTTPSアドレスを開き、端末名と8桁の登録コードを入力します。
5. トーク一覧から会話を選びます。初回のモデル選択は画面に従ってください。
6. 「アプリ情報」の「アプリを追加」、またはChromeのメニューから「アプリをインストール」を選びます。表示されるメニュー名はChromeのバージョンによって異なります。

PWAはHTTPSが必要です。Androidからの `http://192.168...` 接続は正式な導入経路ではありません。証明書の警告を無視して日常利用しないでください。`localhost` のHTTP例外は開発PC自身での検証用です。

ホームサーバーはDesktopとは独立したプロセスです。Desktop画面を閉じても、独立して起動したサーバーは停止しません。PCの電源断・スリープ中は利用できません。LEもDesktopが所有する子プロセスではなく、独立して起動しておく必要があります。常駐化・自動起動・ファイアウォール・外部公開設定は自動変更しません。

## 接続先とデータ

「設定 → 会話を持ち歩く」で接続先の名前とHTTPSアドレスを保存します。切り替えると、そのサーバーの画面を開きます。履歴、画像、ダウンロード、ストリーミングはすべて同じ接続先に向かい、認証情報はほかのサーバーに転送しません。

接続先を変える操作と、会話を移行する操作は別です。キャラ設定の入出力だけでは、記憶を含む会話全体の移行にはなりません。自分のPCに会話を保存し、クラウドのモデルを使っている構成でも、PCを止めると会話は利用できません。

接続先一覧・下書き・表示設定は、そのブラウザーの接続先ごとの保存領域に置きます。ブラウザーのデータ削除で失われます。下書きは暗号化された保管庫ではありません。端末登録を解除しても下書きは残ります。共用端末ではOSのロックとブラウザーのサイトデータ削除を使ってください。

## 切断と更新

送信前に生成IDと入力内容を端末に保存します。復帰時は同じ生成IDの状態と確定履歴を取得して照合し、未確定の間は同じ会話への追加送信・変更を止めます。確定済みの返信を二重に送信しません。保存領域が使えない場合も、送信結果を追跡できないまま送信しません。

Service Workerが保存するのはビルド済み画面、JS/CSS、同梱アイコンなどの指定ファイルだけです。API、会話履歴、利用者の画像は保存しません。オフラインで過去の会話を読む機能や、返信を生成する機能ではありません。

新バージョンは確認してから適用します。他のKyaluluタブが開いている場合は更新を保留します。生成中・編集中の更新を避け、会話の結果を確認してから実行してください。

## サーバー管理との分離

スマホの登録端末から、LEのダウンロード・モデル削除・PC診断・比較実験などは実行できません。外部Hubの検索・URL取得もサーバー側のPCで行います。スマホからのファイル取り込みとキャラ編集は利用できます。

端末を紛失した場合は、サーバーで `devices` と `revoke` を使って登録を解除します。サーバー再起動でもすべての端末登録が無効になります。登録解除より前に受け付けた処理は完了する場合があります。

## 検証とリリース条件

自動検証は実ユーザーのDBではなく専用データで実行します。

```powershell
pnpm --filter web test
pnpm --filter web build
.venv/Scripts/python.exe -m pytest tests -q
```

ブラウザー受け入れテストは `tests/e2e_mobile.py` です。`mobile.kyalulu.test:8443` をloopbackへ解決し、ローカル試験専用の証明書で起動した本番ビルドを操作します。`.artifacts/mobile-v1` 内の専用DBを指定し、実ユーザーのサーバーに対して実行しないでください。テスト中だけ証明書例外を使います。

```powershell
# テスト用証明書・鍵を用意した後、別のターミナルで起動
$env:KYALULU_DATA_DIR = "$PWD/.artifacts/mobile-v1/data"
$env:KYALULU_EXPERIMENTS_DIR = "$PWD/.artifacts/mobile-v1/experiments"
.venv/Scripts/python.exe scripts/home_server.py serve --origin https://mobile.kyalulu.test:8443 --host 127.0.0.1 --port 8443 --cert .artifacts/mobile-v1/test-cert.pem --key .artifacts/mobile-v1/test-key.pem
# もう一つのターミナルから
.venv/Scripts/python.exe tests/e2e_mobile.py
.venv/Scripts/python.exe tests/e2e_pwa_update.py
```

**v1.0.0正式公開の判定には、以下の実機検証も必要です。** ブラウザーのモバイルエミュレーションだけでは代替できません。

- Android Chromeでインストール・ホーム画面起動・更新・戻る操作。
- Gboard日本語変換、ソフトキーボード表示中の入力欄と送信ボタン、文字サイズ拡大。
- 画面ロック／プロセス終了、Wi-Fiとモバイル回線の切り替え、サーバー停止・復帰。
- 使用するHTTPS証明書とネットワーク経路での登録・解除。
- 実際のGemma 4 26B no-think環境で、PCと同じ会話設定・記憶・応答品質・待ち時間。

実施済みの証拠と未実施の項目は [検証記録](validation/2026-09-29-android-pwa.md) に分けて記載します。
