# Core全体復元の実装・架空データ試験の範囲

統合計画の残件であるDB全体の復旧を対象にする。
自動承認レビューは、復元データ・未送信変更の喪失リスクと
「具体的な本番復元範囲の承認が確認できません」を理由に実装パッチを拒否した。

利用者は以下の保護条件付きで実装・架空データ試験を明示的に許可した。
この承認に基づく実装・検証の範囲は次のとおり。

- `runtime/python/local_backup.py` の復旧処理を改訂し、関連helperを再利用する。
- pytestの `tmp_path` 内に新規作成した架空SQLite・Core zipだけで試験する。
- 実装と試験記録を既存の承認済みブランチへcommit/pushし、Draft PRを更新する。
- 本番の会話・DB・モデル・設定・台帳を復元、削除、上書きするコマンドは実行しない。
  本番反映やマージの許可とは区別する。

## 承認された保護条件

1. Runtime/tenantのロック内で復元前の独立Coreアーカイブを作り、その後に復元する。
2. 現在のNative outbox本文/request ID、受領済みtombstone、owner対応を古いDBへ巻き戻さない。
3. ownerが衝突するバックアップは採用せず、現在のDB・媒体を維持する。
4. 復元DBで同期を停止し、旧outboxを本文再送なしで照合する。復元した会話は再確認後に別コピーにする。
5. Cloudの既存リンクにも復元確認を要求する。削除記録を統合し、古いDBから復活させない。
6. 失敗時は現在のDB/媒体へ変更を確定せず、復元前アーカイブと元の入力zipを残す。
7. 台帳・残高・予算・認証ファイル・無関係な作業ファイルは変更しない。

`tests/test_core_restore_sync.py` は全操作対象が `tmp_path` 配下であることを確認し、
既存の架空Cloudアカウントとin-process ASGIを使う。実提供元や本番Cloudは呼ばない。
本番の復元・削除・上書き、マージはこの承認の対象外。
