# Kyalulu Mobile 検証記録 — 2026-10-23

## 公開範囲

公開URLは https://mobile.kyalulu.com/ 。Cloudflare Pagesの専用プロジェクト`kyalulu-mobile`へmobileビルドを配置した。
これは実機検証前の検証版であり、Android/iPhoneの全対応完了を表すものではない。
DNS・証明書の状態はactive、HTTPS応答、CSP、COOP/COEPを確認した。
変更は未コミット。Gitのcommit/push/branch切替は行っていない。

モデル管理、OPFS保存、キャラ編集、会話・下書き保存、JSONバックアップ、ストリーミング、停止、履歴の切詰め、モデル切替、明示PWA更新を実装した。
会話用のAPI・認証・外部推論を使用しない。モデル生成の画像URLによる外部通信も抑止する。
バックアップはキャラ・会話・選択設定を対象とし、モデル本体は含めない。復元上限は32MiB。

## 配布と再現性

GGUF配布先: https://huggingface.co/Naotaka0127/Kyalulu-Mobile-GGUF

3モデル各5分割、計15ファイルを公開した。元GGUFと分割後の全テンソルについて、名前・形状・量子化型・バイト列SHA-256を比較した。
量子化とPLEは維持している。各分割は2GiB未満。単一テンソルを分割できないため、512MiBは目安であり最大ファイルは約1.93GB。
元revision、配布revision、サイズ、SHA-256はカタログと公開provenance.jsonに固定した。

| モデル | 配布revision |
| --- | --- |
| Kyalulu IQ3_M | `4d37b2546568cb4f1d413966483eb8391fe67b92` |
| Google Q4_0 | `e640c670e5ecdf33c21415dbe50c637ce9c4b757` |
| Heretic IQ3_M | `7fbfb600facc6c9ee019fffe7aa2894895686285` |
| Mobile ONNX q2f16 | `a7f19b0ab28252b77cea830f52b8290b2479c87d` |

ONNXは公開ONNX派生版のテキスト用ファイルを使う。元のmobile-ctそのものを実行するものではない。
画像・音声エンコーダーは取得しない。

WASM入力: wllama 3.8.1、llama.cpp `46ca246de9bb1c35269722a6240d37d9dfd79cad`、Emscripten 4.0.20、
Dawn `v20260317.182325`、CMake 3.31.6、Ninja 1.12.1。
通常版とSafari互換版をWSL Ubuntuでビルドした。
`prepare.py`による5ファイルの変更を、固定版の原本から別ディレクトリへ再適用し、実際のビルド入力と一致・再適用時の不変性を確認した。
`scripts/mobile_wasm/ple.patch`が統合差分である。

Pagesの25MiB制限を超えるORT資産は`.gz`で配布し、Service Workerが圧縮ファイルのSRIを検証した後に展開する。
HTTPのContent-Encodingに依存する事前圧縮は、本番で二重圧縮によるSRI不一致を起こしたため廃止した。
モデルはPages成果物とアプリ更新キャッシュに含めない。
`scripts/mobile_release.py`で34論理資産のSRI、展開後のハッシュ、Pages上限、ソースアーカイブを検査する。

## 自動試験・ブラウザ試験

- `pnpm --filter web test:mobile`: 42試験成功。SHA-256、カタログ、IQ3_M固定、バックアップ境界、履歴切詰め、途中応答の扱い、ダウンロード中断・再利用・破損・容量不足・OPFS非対応、PWA更新と圧縮資産を検査。
- Web型検査、通常Webビルド、mobileビルドに成功。通常ビルドの既存chunk-size/Nodeモジュール外部化警告は残る。
- Chromeの390px/1280pxで、キャラ作成、会話・下書き再開、バックアップ書き出しと実際の復元、4候補、破損モデルの拒否、オフライン再起動を確認。
- 本番URLでも同じUI試験に成功。ページ例外0、会話API要求0、自動画像取得0。
- ONNXとKyalulu GGUFで、生成停止、別モデル選択時のdispose/unload完了、元モデルの再読込を確認。これは物理メモリがOSに返った量の測定ではない。
- 専用プロファイルで更新ボタンと確認操作による更新・再読込を実行し、キャラ・会話を含むdataストアとモデル保存完了ストアが更新前後で一致することを照合。その後も既存OPFSモデルでオフライン生成できた。
- 本番サイトのCSP/COEP下で4候補の取得先へRange要求を出し、いずれもHTTP 206・32バイトを取得。全量取得とハッシュ検証はlocalhostの専用アプリで行った結果と区別する。

WindowsのVitest既定fork poolでは一時SSRファイルのENOENTが生じたため、mobile用コマンドではthread pool・1 workerを明示する。
実装不具合の修正後に対象試験を再実行している。

## 実モデルの結果

Windows Chrome 155、headless、AMD RDNA 4 WebGPU、`--enable-unsafe-webgpu`を使用。
専用テストプロファイルで全量ダウンロード・SHA-256検証後、通信を切ってページを再起動し、各モデルの読込・生成を確認した。
設定コンテキスト2,048、出力上限256、Thinking OFF。表は短い1回のスモーク結果で、モデル間の正式ベンチマークではない。

| モデル | 初期化 秒 | 初回トークン 秒 | 生成全体 秒 | 出力トークン | 重み用バッファ合計 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Kyalulu IQ3_M | 4.73 | 1.27 | 1.88 | 20 | 1,513,315,072 bytes |
| Google Q4_0 | 5.21 | 1.16 | 1.85 | 24 | 1,737,251,584 bytes |
| Heretic IQ3_M | 5.11 | 1.22 | 2.43 | 46 | 1,513,315,072 bytes |
| Mobile ONNX q2f16 | 4.28 | 6.22 | 7.58 | 46 | 未測定 |

数値の原本は`.artifacts/mobile-validation/measurements-*-offline.json`。
各結果にはrevision、User-Agent、設定コンテキスト、要求バックエンドを記録する。
停止・切替の再試験により同名JSONが更新された場合、そのJSONが最新の原本となる。

GGUF 3候補で`pleLazy=true`、生成中のPLE行読込を確認した。`pleBytesRead`はモデル読込以降の累積値である。
WASMヒープは774,701,056 bytesだったが、重み用バッファは上表の通り1GBを超える。
これらは物理常駐量ではない。GPU全体、KVキャッシュ、重みの物理常駐量、プロセスの物理メモリは未測定。
「常駐重み1GB未満」の達成を認定しない。GGUFの結果をONNXへ転用しない。

生成成功はキャラクター品質・命令追従性の合格を意味しない。短い返答の指示に長く返した例もあり、品質評価は別途必要である。
未改変npm版とのCPU比較は10分以内に完了せず、数値的等価性を証明していない。
ページのWebAssembly機能を変更するだけではWorkerの互換経路を強制できないため、その旧模擬試験は互換版の証拠から除外した。
実バイナリの直接指定による検査は`mobile_wasm/verify_runtime.py`と`runtime-variants.json`を参照する。

同じ固定Kyalulu IQ3_M・同じgreedy入力で、実際の通常版と互換版を直接指定したところ、両者とも「こんにちは。」を生成した。
これは短い1例での一致であり、未改変版との全面的な数値的等価性ではない。

| 直接実行 | 読込＋生成 秒 | WASMヒープ bytes | PLE行読込 |
| --- | ---: | ---: | --- |
| 通常版 WebGPU | 5.52 | 774,701,056 | 有効 |
| 互換版 WebGPU | 6.03 | 739,377,152 | 有効 |
| 通常版 CPU | 49.69 | 1,815,347,200 | 有効 |

この直接検査だけはコンテキスト512・最大出力8の専用fixtureで行った。CPU経路も生成したが、GPUと同じ出力になることは要求していない。
後続の測定JSONには実際に選ばれた`runtimeVariant`と、prefillを含む全処理平均の`tokensPerSecond`も保存する。
`firstTokenMs`は最初の表示可能なストリーム文字列までの時間である。純粋なdecode速度やモデル内部の最初のトークン時刻とは区別する。
