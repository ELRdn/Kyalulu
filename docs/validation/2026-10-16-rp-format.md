# RP形式 v1.1のローカル検証

仕様: [RP_FORMAT.md](../RP_FORMAT.md)。2026-10-16、ユーザー承認に基づく変更。

- `*（…）*`はassistant/LLMの返答本文に残し、括弧を含めユーザーに表示する。創作上の内心であり、他キャラクターが聞いた台詞として扱わないよう生成契約へ指示。
- `@:`の明示だけでナレーター枠を作る。名前指定・単独の動作・内心からは作らない。全角ラベル・旧NARRATOR入力を受け付ける。
- 標準プロンプトとNative/Portable共通の生成契約を更新。Cloudも同じ`generate_events`を経由する。標準プロンプト版は`prompt:character-runtime@0.1.5`。
- `text.test.ts`と`MessageContent.test.tsx`: 15件合格。共通例5件、動作の誤分類防止、内心のHTML表示、明示ナレーション、全角ラベル、引用・エスケープ・コードフェンス、生成途中を検査。
- `test_generation.py`・`test_portable_runtime.py`・`test_conversation_parity.py`: 41件合格。Native/Portableへの共通生成指示と内心本文の保持を模擬プロバイダーで検査。
- Webの型検査と本番ビルドに成功。ビルドはtheme-initのscript属性・noise-cのNode組込モジュール・チャンク容量の警告あり。
- 変換ツールは46件のunittestとJavaScript構文検査に合格。両プロジェクトの正解例JSONのSHA-256は同一。
- Windowsの既定一時ディレクトリで検証が失敗したため、プロジェクト配下の検証用TEMPとpytestのbasetempで再実行。

既存ログ・学習データの一括更新、本番反映、実モデルの会話品質・知識境界の遵守、実ブラウザでの見た目は未検証。内心を共有済みの事実にしないことは生成指示であり、意味上の遵守を機械検証したという結果ではない。
