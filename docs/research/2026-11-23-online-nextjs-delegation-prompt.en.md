## Architecture to deliver

- Give Next.js ownership of online page URLs, layouts, public HTML, metadata, loading states, error states, and navigation. Keep the online application on its existing origin so links, cookies, browser storage, and installed PWAs retain their identities.
- Keep FastAPI authoritative for authentication, authorization, generation, memory, persistence, quotes, credit reservations, settlement, synchronization, and publication eligibility. - Use Server Components for suitable public reads and Client Components for input, personal preferences, draft recovery, IndexedDB, OPFS, model workers, and remote connections. Keep public output independent of private browser data. Public character details should load the requested character without waiting for the entire catalog, worlds, or the viewer's sessions.
- Support online device and remote-PC screens in the new frontend. Preserve browser-only inference, offline startup, and arbitrary device-local conversation IDs through a client shell that can be cached and opened offline. Electron and the locally distributed PC application may keep their packaging and shared UI dependencies. The separate marketing and documentation site is outside this migration.
- Follow repository conventions when choosing package location, Next.js version, and deployment method. Record the rationale for consequential choices. Retain one source of truth for each domain rule and extract shared components only when there is a real caller.
