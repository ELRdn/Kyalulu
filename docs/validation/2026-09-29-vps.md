## Backup and recovery

- `kyalulu-backup.timer`: daily03:30 JST plus up to15min jitter, persistent.
- SQLite online backup includes committed WAL state. An in-memory snapshot is
  integrity/schema-checked, then streamed to age encryption.
- Files: root-only `/var/backups/kyalulu/relay-*.sqlite3.age`, approximately30-day
  retention, single-writer lock, atomic completion. No plaintext snapshot on VPS
  persistent storage. Recipient file contains only the PC's SSH public key.
- First encrypted snapshot was copied off-VPS to the PC. Decryption and SQLite
  integrity/schema validation passed in an isolated temporary directory; the
  plaintext temporary recovery files were removed afterwards.
- A first attempt to deserialize the WAL-format snapshot directly into an
  in-memory SQLite database failed. Restoring to a real isolated file succeeded;
  this is the documented recovery route.
- Snapshot service succeeded again after reboot (`Result=success`, exit0).
- Off-VPS copies are currently manual. External outage notification and automatic
  offsite backup are not configured. Preserve the recipient's private key safely:
  losing it makes those backups unrecoverable.
