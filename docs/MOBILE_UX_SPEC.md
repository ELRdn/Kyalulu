## 2. 初回導線

1. 最初の画面は**ホーム**。検索から来た人は**キャラページ**に直接着地する。オンボーディングのフォームは置かない。
2. カードをタップすると**会話プレビュー**を開く（公開URL）。キャラのイントロ（固定文）を即表示する。LLM費用はかからない。
3. 入力欄の上に、作者が設定した**最初の一言の候補**を並べる。
4. 入力欄または候補をタップした時点で**ログインシート**を出す（文字を打つ前に出す）。
5. ログイン完了後は**同じ会話に戻り**、選んでいた候補を自動送信する。返事を待つ間は、キャラの動作（「紅茶を淹れています…」）で状態を表す。

削除するもの：オンボーディングの実行先選択・言語・居住国（ISOコード手入力）・年齢・同意の画面、興味選択3画面。

## 3. ログインシート

ログインの入口は**このシート1つ**に統一する（会話、トーク、マイページ、つくるの全てから同じものを開く）。

- 文言は文脈とベネフィットで書く。例：「シオンとの会話を保存して続けよう」。
- 主ボタン（この順）：**Google**／**Apple**／**ChatGPT**。
- 折りたたみ1行：「メールで続ける」。電話番号は最初の公開では出さない。
- LINEは入れない。
- 同意・年齢・地域の確認は**このシートだけ**で行う。地域はブラウザのロケールから推定し、変更可能にする。
- ここでの年齢確認は利用可能年齢（14歳以上、§7）の自己申告まで。成人向け機能の解放は別の年齢確認（§7）で行う。
- ボタンが増えても配置が崩れない作りにし、準備できた手段から表示する。

| 手段 | 状態 | 必要なこと |
|---|---|---|
| Google | 実装済み | — |
| メール | 実装済み（メールリンク） | 独自SMTP配信の受け入れ |
| Apple | Supabase標準対応。後日（オーナーがDeveloper Programに加入予定） | Apple Developer Program、Service ID、ドメイン検証。ボタンはAppleのガイドライン準拠 |
| 電話番号 | 最初の公開では出さない | 入れる場合はTwilio Verify。送信回数制限とボット対策は必須（SMSは送信ごとに費用がかかり、濫用の損失が大きい） |
| ChatGPT | OpenAIの限定提供 | オーナーが申請中。承認までは非表示。Supabaseのカスタム OIDC として追加（1プロジェクト3つまで） |

解析の初期値（2026-11-03 決定）：EU・英国・スイスは**オフ**で、本人の同意後に開始する。それ以外の地域は**オン**で、いつでもオフにできる。地域はこのシートの地域で判定する。プライバシーポリシーの記述もこの形に統一する（現行は「既定オフ」と「標準で有効」が混在）。

## 4. 共通シェル

- ヘッダーは**1段**。現状の「オンライン」帯と「実行先」帯は削除する。
  - オンライン表示はオフライン時だけ出す。
  - 実行先（Cloud／この端末／自分のPC）は 設定 › 上級者向け へ移す。
- ボトムナビは5タブ：**ホーム／さがす／トーク／つくる／マイページ**。「設定」は「マイページ」に改名する。
- 選択中のタブはピル型の薄い紫で強調する。中央FABは使わない（初回の主役は会話）。
- 画面の見出しはタブ名と一致させる（「ディスカバー」「クリエイト」は使わない）。
- 技術情報（実行先・外部送信・保存先・モデル）はチャットヘッダーから外し、**会話設定**に集約する。

2026-11-05 実装（フェーズ3）：

- 状態の帯は、オフラインのときと更新があるときだけ出す（`MobileAppStatus` の `quiet`）。アプリの追加・更新の確認は帯の中にあるため、普段は開けなくなる。マイページの作り直し（フェーズ5）で置き場所を作る。
- サイドバーとボトムナビを同じ5タブ（ホーム／さがす／トーク／つくる／マイページ）にそろえた。画面の見出しと文中の「ディスカバー」「クリエイト」「プロフィール」も合わせた。
- 実行先の帯はまだ全画面に出ている。マイページ › 上級者向けへの移動はフェーズ5で行う。未ログインの人はマイページを開けず（ログイン必須のルート）、ブラウザのE2Eテスト（`e2e_unified_entry`、`e2e_cloud_target_switch`、`e2e_device_target_switch`、`e2e_remote`、`e2e_commercial_ui`）も全画面の帯を前提にしているため、マイページを未ログインでも開けるようにするのと一緒に直す。
- チャットヘッダーの技術情報はフェーズ6で移す。

## 5. 画面別

### 5.1 ホーム

- 「今日の一人」の大きな1枚＋2列カード。
- カードは画像主体。名前の下に**場面の一言**（作者が書く。プロフィール文は使わない）。
- ♡／× ボタンはカードの外に浮かせない。
- コメント数・ランキングは出さない（キャラが少ない間は、出せる実数がなく、数字を捏造しない方針）。
- アプリ誘導・課金バナー・新機能の吹き出しを重ねない。

### 5.2 会話プレビュー／キャラ詳細

- カード（ホーム、さがす）の「話してみる」は**会話プレビュー**を開く。
- 詳細（紹介・プロフィール・ワールド）はシートで開く。
- `speaking_style` などプロンプト用の指示文は表示しない（§6）。

### 5.3 チャット

- ヘッダー：戻る、アバター、名前、状態（キャラの動作で表す）、会話設定。
- 配置はNEWDESIGNの確定事項どおり：ユーザーは右、キャラは左、地の文は左で区別する。
- 入力欄：`*` ボタン（行動 `*…*` を挿入。必須）、返信の提案、入力、丸い送信ボタン。
- **進む**：専用ボタンは置かない。入力欄が空のとき送信ボタンの表示を「進む」に変え、空のまま送るとキャラが話を進める。サーバーが空の送信を受け付けるかは実装時に確認する。
- **返信の提案**：
  - 「提案」ボタンを押したときだけ3件作る（毎ターン自動では作らない）。
  - タップで入力欄に入り、編集してから送れる。
  - 1ターン目は作者の `opening_replies`（§6）、2ターン目以降はAIが生成する。
  - 生成は会話と同じ系統で行う（成人向けの会話ならGemma。OpenRouterへは送らない）。
  - 当面クレジットは消費しない。
- 心の声の専用表示は作らない（2026-11-03 決定）。表現は `*…*`（仕草・情景）と台詞の2種類に絞る。必要になったらキャラ設定で `（…）`＝心の声と決め、表示だけ変える。
- タイムスタンプと既読表示は出さない（没入を優先）。

### 5.4 トーク

- 未ログイン：空状態（「話した相手がここに並びます」）＋おすすめ2人。ログインは小さなリンクで、共通シートを開く。全画面のログインフォームは出さない。
- 初回会話の後：一覧が1件の間は、下に「**次に話すなら**」を出す。
- 会話が増えたら：「ピン留め／最近」の2区分。左スワイプでピン留め・削除。一覧の一言はキャラの最後の台詞。

### 5.5 さがす

- 検索欄を最上部に置く。
- **タグチップ**を1行・横スクロールで出す。中身は人気タグの上位を自動で並べる（運営が候補を固定しない）。キャラ一覧の前にタグを何行も並べない。
- 検索は2本立て（2026-11-03 決定）：
  - タグの完全一致（`#執事` など）。
  - 文章の意味で探す検索（例：「疲れたから甘やかされたい」）。キャラの紹介文・タグ・場面の一言をembeddingにし、サーバー内で動かす。
  - embeddingのモデルは候補 EmbeddingGemma 2（Apache 2.0、多言語、画像も扱える）。キャラ数が少ない間はCPUで足りる。外部APIへは送らない。
- ワールド → キャラ一覧（2列）の順。
- 準備中の「公開作品」と「外部Hubから連れてくる」は利用者向けの画面に置かない。
- 「成人向け」チップ（§7）。

### 5.6 マイページ

- 順序：プロフィール → 統計（出会った／会話／作った）→ 保存したキャラ → 作ったキャラ → ペルソナ → クレジット → 設定（1行）。
- 接続先・同期・同期トークン・Studio・Research・Status は 設定 › 上級者向け の奥へ移す（PRODUCT_SPEC §13）。
- 同期画面に会話本文の抜粋を出さない（キャラ名と件数のみ）。
- 未ログイン：ログインボタン1つ（共通シート）＋表示設定・ヘルプ・規約だけ。

### 5.7 つくる

- 未ログイン：完成見本（公式キャラ）＋「3つ決めるだけ」（名前と姿／場面の一言／最初のセリフ）。CTAを押した時点でログインシート。
- ログイン後：CTAは「新しくつくる」1つ。取り込みは1行に畳み、形式名（SillyTavern等）は取り込み画面の中だけで出す。
- AIによる下書き生成は今は入れない。
- 作成画面の中身はNEWDESIGN §31 に従い、本書では固定しない。

### 5.8 空状態・エラー・404

どれも**1文＋ボタン1つ**。絵はKyaluluのマスコット（NEWDESIGN §27）。文言に絵文字は使わない。

| 画面・状況 | 文 | ボタン |
|---|---|---|
| トーク（未ログイン） | §5.4 のとおり | — |
| トーク（ログイン後0件） | まだ誰とも話していません。 | キャラをさがす |
| さがす（検索0件） | 「◯◯」に合うキャラは見つかりませんでした。 | 条件をリセット |
| マイページ（保存0件） | 気になるキャラを保存すると、ここに並びます。 | キャラをさがす |
| マイページ（作成0件） | まだキャラを作っていません。 | 3つ決めて作る |
| 返信の生成に失敗 | チャット内にキャラの動作として：（返事がうまく届かなかったみたい） | もう一度 |
| オフライン | 上部の細い帯：オフラインです | なし（復帰で自動的に消す） |
| クレジット不足 | シート：残り0です。続けるにはクレジットが必要です。 | クレジットを見る |
| 年齢確認に失敗 | 確認できませんでした。身分証で確認できます。 | 身分証で確認 |
| キャラが削除・非公開 | このキャラは今は話せません。 | 似たキャラを見る |
| ログインに失敗 | ログインできませんでした。別の方法も選べます。 | もう一度 |
| 404 | そのページは見当たらないみたい… | ホームにもどる |

404とエラーには、**泣いている全身絵**（`pose-cry`）を使う。

マスコット（2026-11-05 決定）：SDキャラのE2に作り直した。基準は `reference/kyalulu_mascot_character_sheet_E2.png`。

- 原画（透過PNG、1254px）は `apps/web/public/mascot/e2-v2/`。アプリは余白を詰めてwebpにした `apps/web/public/mascot/v2/` を使う（表情256px、全身320px、`pose-lounge` は480px幅）。
- 使い分け：ロゴ・アバター・待機表示は `face-default`、ホームの挨拶は `pose-wave`、サイドバーは `pose-float`、空状態は `pose-wave`／`face-smile`／`face-excited`／`face-shy`／`face-sleep`、404・キャラを読み込めない・アプリのエラーは `pose-cry`。
- 旧マスコット（`mascot/v1.2/`、`cry.png` など）はアプリから参照していない。

| 幅 | ナビゲーション |

## 6. データモデルへの追加

作者が設定する項目。フィールド名は案。Python／TypeScript（`packages/schemas`）／portable形式／キャラYAML／つくるUIに同時に追加する。

| 項目 | 案 | 用途 |
|---|---|---|
| 場面の一言 | `hook` | ホーム・さがすのカード |
| 最初の一言の候補 | `opening_replies`（2〜3件） | 会話プレビューの候補ボタン |
| タグ | `tags`（自由入力、最大10個） | さがすのタグ検索・タグチップ |
| 公開用の話し方 | `speaking_style` をプロンプト用と公開用に分ける | 詳細画面に指示文を出さないため |

タグの扱い：

- 表記ゆれを統一して保存・検索する（全角と半角、ひらがなとカタカナ、大文字と小文字）。
- 禁止ワード（未成年を示す語など、§7の禁止事項に当たるもの）を含むタグは保存させない。
- 成人向けのタグは、年齢確認していない人の検索・タグチップには出さない。

2026-11-05 実装：

- 公式キャラはYAMLのトップレベル（`hook`、`opening_replies`、`tags`）。作者が作るキャラは保存形式の `data` に同じ名前で入れる（`data` は未知のキーも保ったまま編集・書き出しできるため、形式の変更は不要）。
- 保存時の整形は `runtime/python/core/author_fields.py`（ライブラリの書き込み口 `_write` で必ず通す）。編集画面は `apps/web/src/lib/authorFields.ts` で同じ規則を先に示す。上限は、タグ10個・1つ20文字、場面の一言60文字、候補3つ・1つ100文字。
- タグは入力どおりに保存し（全角記号・先頭の#は整える）、重複と禁止の判定は「全角半角・大文字小文字・ひらがなカタカナ」をそろえたキーで行う。禁止ワードは完全一致だけ（部分一致だと「ゴスロリ」なども止まるため）。
- 公開用の話し方は、別の項目を作らない。キャラページで `speaking_style` を表示しないことで対応する（§5.2、フェーズ4）。
- 成人向けタグを隠す処理は成人向け機能と一緒に入れる。端末内ライブラリへの取り込みは、まだ整形を通していない。
- 公式キャラ7人分の文言は下書き（オーナー確認待ち）。

## 7. NSFWとCloud系統

| 系統 | 方針 |
|---|---|
| 自社ファインチューニングのGemma 4（レンタルGPU） | NSFW可。性的表現・暴力表現ともに可 |
| OpenRouter経由 | 実質SFW。グレーはモデルが拒否しなければ可。UIで「NSFW禁止」を強調しない |

どちらの系統でも次は禁止。モデルが拒否するかに任せず、入出力のチェックで止める。

- 未成年の性的表現と性的搾取（架空のキャラを含む）
- 実在の人物の性的表現
- 現実の犯罪を実行する手順

規約の方針（2026-11-03 オーナー決定）：

| 項目 | 決定 |
|---|---|
| 利用可能年齢 | Zetaと同じ。報道では14歳以上（Zeta日本語版の規約本文は未確認）。18歳未満は保護者の同意 |
| 対象地域 | 全世界 |
| 成人向け機能の解放 | 外部の年齢確認サービスで18歳以上を確認できたアカウントだけ。全地域共通。自己申告では解放しない |

年齢確認：

- **確認のタイミング**：成人向けをオンにするとき、または成人向けキャラに初めて話しかけるとき。登録時には求めない。
- **方式**：まず顔による年齢推定。判定が際どい場合（例：推定25歳未満）だけ身分証の確認に進める。
- **費用**：1人1回目は運営が負担する。当面は再挑戦も無料。
- **保存するもの**：結果（確認済み、方式、日時、事業者の参照ID）だけ。顔・身分証の画像は保存しない。
- **確認結果の受け取り**：事業者からサーバーへ直接届く通知（Webhook）で受け取り、アカウントに付ける。クライアントからの申告は信用しない。
- **事業者**（2026-11-03 決定）：Yoti。予備はPersona。Stripe Identity は成人向け事業での利用に懸念があるため外す。
- 理由：英国（Ofcom・ICO、2026年3月、自己申告は有効と認めない）、豪州の業界規範、米国の州法が、成人向けコンテンツに実効的な年齢確認を求めている。

表示：

- NSFWキャラは**未ログインでも表示する**（露骨でないサムネイルとタイトルに限る）。ただし初期は一般向けのみ。「成人向け」チップを押すとブラウザ単位で一度だけ年齢の自己確認を出し、「はい」の後はホーム・一覧にも混ぜる。
- 会話にはログインと、上記の年齢確認が必要。
- マイページの「成人向け」切り替えはオフが初期値。オンにする時点で年齢確認を求める。オンにすると `nsfw: true` のキャラはGemma系統で動く（系統の違いはユーザーに見せない）。
- サムネイルは露骨でない画像に限る（作者向けルール）。露骨な画像は会話の中だけ。
- 「クラウドはSFWのみ」の文言（`CloudLogin.tsx`、`CloudSettings.tsx`）はUIから外す。

検索：

- NSFWキャラのページも**インデックスする**。
- URLを分ける（例 `/characters/r18/:id`）。`<meta name="rating" content="adult">` を付ける。
- ページはサーバー側で描画し、本文（露骨でない説明とサムネイル）を返す。未確認の訪問者には年齢確認を重ねて表示する。
- タイトル・説明・OGPは一般向けの表現にする。

系統の運用（2026-11-03 決定）：

- **GPU**：RunPod の Secure Cloud、米国リージョン。常時起動ではなく Serverless（使った秒数だけ課金）にする。
- **入出力の自動チェック**：小型の判定モデルを同じGPUで動かす。外部の検査APIへは送らない。
- **料金**：成人向けの会話も通常の会話と同じクレジット消費にする。最初の1か月で1回あたりの原価を測り、赤字なら全体の単価を見直す。
- **成人向けキャラの事前審査**：
  1. 判定AIが説明文と画像を見る。画像は年齢が低く見える人物の有無を判定できるモデルを使う。
  2. 「明らかに問題なし」だけ自動で公開する。
  3. それ以外は運営が審査する（目安72時間以内、却下には理由を1行付ける）。
  4. 自動で公開した分も約10%を抜き取りで人が確認する。
  - AIだけで通す審査がMastercardの事前審査の規則を満たすかは、決済代行の審査時に確認する。
- **Gemma 4のライセンス**：Apache 2.0 に変わったと報じられている。従来のGemma利用規約が禁じていた性的なチャットボット用途に当たらないかを、Googleの一次資料（ライセンスとモデルカード）で確認してから提供する。

## 8. ルーティングとSEO

- `HashRouter` を `BrowserRouter` に置き換える。キャラページ・会話プレビュー・公開作品は、ログインなしで開ける公開ルートにする。
- `apps/web/src/main.tsx` のコメントのとおり、Electron版は `file://` 配信のためHashRouterを使っている。Desktopビルドだけ HashRouter を残すなど、Electronを壊さない形で移行する。
- 公開ルートはサーバー描画またはプリレンダーで、検索エンジンに本文を返す。
- 未知のパスはホームを黙って表示せず、404を返す。
- 2026-11-03 実装：Web（Cloud・Core）は `BrowserRouter`、Electronと `/device/` シェルは `HashRouter` のまま（`apps/web/src/main.tsx`）。
  旧 `/#/...` のURLは読み込み時にパスへ置き換える。サーバー（`WebDist`）は未知のパスでもアプリ本体を返しつつ、状態コードを404にする。
  公開ルートは、Cloudサーバーが返すHTMLに、タイトル・説明・canonical・OGPと本文を差し込む（`runtime/python/cloud/public_pages.py`）。
  対象は `/discover` と、`characters/*.yaml` のうちSFWのキャラページ。作品・作者ページは公開Communityの提供開始時に追加する。
  `index.html` の `noindex` は公開開始の判断まで残す。
