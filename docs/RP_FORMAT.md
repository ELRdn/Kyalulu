# Kyalulu RP形式 v1.1

2026-10-16合意。アプリ表示、通常のLLM生成、変換ツール、今後の学習データで共通の意味を使う。作業JSONの版はv1のまま。

| 記法 | 意味 |
|---|---|
| 通常文 | 現在の話者の台詞 |
| `*カップを置く*` | 現在の話者の動作・外から見える反応 |
| `*（もう少し話していたい）*` | 現在の話者の内心の独白 |
| 行頭の `@:` | 独立したナレーションの開始 |
| 行頭の `@名前:` | 話者の指定・切替。ナレーションを終了する |
| `@USER:` | ログ・学習データのユーザー話者 |
| 単独行の `---` | ログ・学習データの会話ターン境界 |

## 内心の可視性と知識

- assistant/LLMが`reply`に出力した`*（…）*`はユーザーに表示する。括弧を残し、動作と同様に控えめに表示する。内心専用の折りたたみやナレーター枠は作らない。
- USERが書いた内心も、そのUSERの独白。相手キャラクターが聞いた台詞にはしない。
- 他の登場人物は、独白を読めた前提で応答しない。読者が知っていることと作中で共有されたことを区別する。
- USERの台詞・動作・内心・決断をAIが勝手に確定しない。
- 内心を記憶・要約する場合も、誰の独白かを維持し、聞いた事実や共有済みの知識へ変えない。
- 創作上の独白であり、モデル内部の推論とは別。通常の生成は既存の`reply`と`state_update`のJSON契約を維持する。

知識の境界は生成指示で伝える。記号の解析だけで実モデルの遵守を保証できるものではない。

## ナレーションと互換性

`@:`の本文は次の`@名前:`まで続く。地の文は`*…*`で囲んで出力する。`@名前:`、単独の`*動作*`、`*（内心）*`はナレーション開始条件にしない。通常の一対一の返答では話者ラベルを省略できる。

出力ラベルは半角`@`と`:`。全角`＠`・`：`はラベル部分だけ入力別名として受け付ける。本文全体のUnicode正規化はしない。旧`NARRATOR:`/`@NARRATOR:`も明示ナレーションの入力別名として受け付ける。旧アプリ表示との互換性のため、この旧形式だけは空行でも描写を終了する。変換ツールはこれまでどおり明示された次の話者までを同一話者として解析し、正規の`@:`で出力する。

引用・説明中の記号を構造にしたくない場合は`\@`・`\*`を使う。アプリ内のコードブロック・引用ブロックの記号は話者ラベルとして解析しない。生成途中の閉じていない記号を理由に本文を隠さない。

```text
@キャルル:

*カップをそっと置く*

*（もう少し話していたいな）*

もう一杯、飲む？

@:

*窓の外で雨が降り始めた。*

@キャルル:

あ、雨だ。
```

## 変換・今後の学習データ

原文の本文・括弧・話者を保持する。変換作業JSONでは内心を既存の`action`の一種として保持し、`*（…）*`で区別する。ナレーターへ付け替えたり、内心の文章を新しく生成したりしない。内心への変更に括弧の追加が必要なら、原文保持の変換では自動追加しない。

新規データの書式は上記を使用し、USER/assistantの役割と`@名前:`の作中話者を区別する。既存ログ・学習データは一括変更しない。共通の正解例は`tests/fixtures/rp-format.json`。変換ツールにも同じ例を置き、構造・本文保持・再解析の安定性を確認する。
