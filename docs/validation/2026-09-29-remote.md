# Kyalulu Remote — implementation and validation, 2026-09-29

## Outcome

Implemented the Android PWA → opaque Relay → PC Host → existing Runtime path.
The development candidate passes local integration and regression tests. It is
**not certified for public v1.0.0 release**; package versions remain 0.1.0.
No Git commit/push, VPS purchase, deployment, real data adoption, startup task
registration or model process change was performed.

The implementation uses pinned standard Noise XX with QR Host pinning, one-use
enrollment, PC confirmation, persisted device pins/revocation, DPAPI on Windows,
bounded encrypted API/media transport, detached generation and durable recovery.
The original direct HTTPS PWA and Desktop remain supported. Cloud inference,
cross-Host state sync, P2P, notifications and native app-store distribution remain
out of scope. [Setup and detailed limits](../REMOTE.md).

## Problems found and repaired during implementation

1. An initial JS Noise candidate used the wrong nonce for REKEY. It was rejected.
   The adopted unmodified WASM implementation does not expose REKEY; the explicit
   policy uses fresh XX sessions instead. The wrapper is archived upstream, so
   external security review remains mandatory before public release.
2. A naive loopback proxy would inherit PC administrator privileges. The Host
   now passes an internal typed principal through the full security middleware,
   with a live revocation callback, exact route allowlist and session checks.
3. Concurrent initial GETs could exhaust attachment assembly slots. Small
   requests now use single frames; browser admission is bounded before reading
   bodies. Stalled body reads are cancelled on abort, close and deadline.
4. Fast large-file responses could overrun replay buffers or trip Relay rate
   limits. Host/client output is paced and non-generation downloads apply
   bounded backpressure; generation work remains independent of the socket.
5. Naive image URL acceptance allowed normalization/srcset paths outside encrypted
   RPC. Remote rendering now permits only exact public image paths or authenticated
   Runtime downloads; unused Blob URLs are released.
6. Closing a connection while WASM initializes could later create a socket. The
   lifecycle is checked again after initialization, before opening a socket.
7. Strict CSP blocked the old inline theme initialization and external fonts.
   Theme initialization is same-origin; fonts use the system stack. WASM is
   included in the explicit build/SRI Service Worker asset allowlist.
8. Host startup with existing data needs process ownership: Runtime recovery must
   not mark another live process's generation interrupted. Current lifespans use
   a common OS lock, and explicit existing-data adoption creates a backup first.

## Release gates still open

1. Actual Android installation/update, Japanese IME, screen lock/process termination,
   real Wi-Fi/mobile transitions, and production certificate chain.
2. The user's exact Gemma 4 26B/no-think profile, quality/memory parity and observed
   display latency versus the PC baseline. Read-only checks of default LM Studio
   `127.0.0.1:1234` and LE `127.0.0.1:8130` timed out during this run; no model was
   started, stopped or reconfigured. This does not establish all possible endpoints
   are unavailable.
3. Completed 24-hour run and production-like external-network tests. The p95
   additional latency target of 300ms has **not** been accepted from a loopback test.
4. External cryptographic/authorization review, including the archived WASM
   dependency and the PWA distributor/endpoint trust boundary.
5. Authorized VPS/domain selection, actual costs, Caddy/TLS deployment, off-machine
   backup restore, and a tested rollback against a prior deployed version. Current
   dummy-DB restore tests do not prove schema downgrade compatibility.
6. Remote GitHub CI execution after an authorized publication workflow. Its updated
   workflow is present, but no remote CI run is claimed here.

Only after these gates pass should a v1.0.0 version bump/public release be approved.
